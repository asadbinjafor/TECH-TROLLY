# Blank money input audit — 2026-10-30

All 16 commands use the same field metadata and preparation rules on web/native. This follow-up supersedes the earlier zero-prefill decision; real zero balances, reports and saved invoices still represent actual accounting values.

| Inputs                                      | Blank handling / dependency                                                                                                                                      |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Every numeric input                         | Starts empty, including sale-unit changes. Ordinary optional-zero drafts reopen blank; explicit required cash-count zero remains deliberate.                     |
| Sale discount                               | Always optional; blank becomes decimal zero. Net price must remain positive.                                                                                     |
| Sale Cash / Bank                            | Each optional. Full payment in either accepts the other blank; mixed payments keep both entered amounts. Nothing auto-fills or erases the other side.            |
| Partial / all-credit sale                   | Difference remains customer due; saved Customer becomes required. An overpayment is rejected before confirmation and by PostingService.                          |
| Purchase courier / paid                     | Optional zero; unpaid merchandise remains supplier due. Treatment required only for courier cost. Account required for paid merchandise or courier cash outflow. |
| Opening Cash / Bank                         | Each may be blank/zero, including an empty opening balance.                                                                                                      |
| Salary advance adjustment                   | Optional zero. Account required only for the remaining salary payout; existing advance availability and salary uniqueness checks stay authoritative.             |
| Price, acquisition cost, transaction amount | Empty or zero rejected; zero-allowed fields do not weaken these requirements.                                                                                    |
| Cash count                                  | Required intentional value, including explicit zero. Existing mismatch reason rule retained.                                                                     |
| Pending submission                          | Exact saved canonical payload and idempotency key retained; draft cleanup does not touch uncertain commands.                                                     |

Blank-to-zero conversion applies only to explicitly marked zero-allowed fields while preparing a new command, before idempotency persistence. Decimal strings and BigInt precision remain unchanged. Invalid formats, negative values, excessive precision and unknown selections are still rejected. Optional unused account/treatment selections use existing inert enum defaults in payloads. No account entry is generated by a zero amount.

Checks: API/web builds and workspace typechecks; 22 hosting/form checks, including each command and required blank, both payment directions, split/discounted payments, credit, maximum decimal value, old drafts and dependent fields; 22 isolated PostgreSQL checks. A separate explicitly created disposable shop exercised real prepared Cash/Bank/credit postings, repeated keys and journal/balance reconciliation. Browser Review passed for both single-account payments, blank Discount, and 390px layout; excess payment was blocked. Captured browser error log was empty. The test shop and its own servers are removed after use; the separate persistent local database is preserved.

No production business test records, schema migration, paid hosting change, or change to posting transactions, journal immutability, authorization or same-origin cookies. Native source/typechecks share the new rules; physical Android/iOS device acceptance remains unverified. Release evidence is in progress.md.
