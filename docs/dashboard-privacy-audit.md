This is on-screen dashboard privacy for an already authenticated authorized user, not a new data-access boundary: existing protected state responses still contain their authorized data. No stronger profit confidentiality is claimed.

Tapping any amount's reveal control opens a password dialog for the current account. Authenticated `/auth/verify-password` checks that account's current bcrypt hash server-side, verifies its still-valid session again under locks, and returns a 60-second display duration. It creates no session, persistent unlock token or role permission. A persistent per-account auth_attempt key allows at most five failed guesses per 15-minute window across sessions; success clears that verification counter. Passwords are neither stored in browser/native storage nor logged; the input is cleared on submission/close. Wrong passwords, revoked sessions and another account's password cannot reveal through the UI.

Web reveal state lives only in memory, is bound to account and page, expires after one minute, and clears on hide, window blur, hidden page, pagehide, navigation or reload. Open dashboard financial detail/receipt dialogs close when relocking. Native mirrors the mask/password/duration behavior and clears on AppState background/navigation blur. It also ignores late verification results after cancellation/background. Existing host-only HttpOnly cookies and same-origin proxy remain intact. No database migration or business data edit.

The four overview quick actions use larger icon cards: Purchase blue, Expense pink, Transfer green and Loan purple, with directional chevrons. Web switches from four desktop columns to two phone columns; native uses a two-column grid. Existing form handlers are reused. No generated image asset or new dependency is required.
